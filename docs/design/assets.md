Maintain an asset manifest with creator, canonical URL, date obtained, license/permission record, attribution, permitted edits, local filename and focal coordinates. Missing rights → substitute owned placeholder and flag the blocker. Never use scraped character PNG sites as provenance.

Proposed budgets per asset: hero ≤250KB mobile / ≤450KB desktop, thumbnail ≤50KB at normal card width. Serve responsive widths 320/640/960/1440 as appropriate. Set dimensions and sizes; load visible lead eagerly, remaining shelf images lazily. Test on a throttled mobile profile and with images disabled. Use alt text only where artwork contributes information beyond adjacent text.

### Design sidecar and observed parity

`.impeccable/design.json` follows the installed Impeccable 4.8.0 document reference's `schemaVersion: 2`: color and typography metadata, interaction shadows, motion, breakpoints, narrative, and nine self-contained component snippets. CSS custom properties remain live-bound with literal fallbacks, and icons are inline SVG. There is no legacy `tokens` array. Synthesized eight-step color ramps are panel aids, not approved application palette additions.

The approved `DESIGN.md` is a review-package document without YAML token frontmatter or the document command's canonical eight-section structure. It also preserves the package's original “draft” and “proposed” wording. This appendix records that existing format difference without revising the approved source; it does not block implementation or require an unrelated document rewrite. Sidecar color metadata therefore names the observed CSS variables; it does not claim that missing frontmatter exists. Component entries deliberately omit `refersTo` links to nonexistent frontmatter tokens. Narrative text is quoted from the approved document; absent named-rule and do/don't lists remain empty.

Observed parity in `src/app/globals.css`: paper `#F9EBD7`, ink `#0F0F0B`, action `#CF102C`; Anton 400 and Source Sans 3 400/600/700; 3px control corners; 1px rules and 1.5px control borders; 44px minimum primary controls; 16/24/32px page gutters across the 600/960px breakpoints; 1200px content maximum; the documented 5:7 auth, 7:5 feature, 4:8 details and 3:7 profile splits; two/four/six-column shelf progression; and 120ms control transitions with reduced-motion override.

Observed differences from the approved numeric proposals are documented rather than silently promoted into design authority: base desktop `h1` uses 56px × 1.08 = 60.48px line-height instead of 58px; base section headings inherit 1.08 instead of the proposed 28/34px line-heights; base paragraph line-height is 1.45 (23.2px phone, 26.1px desktop) rather than 24/26px. Shared action text is 18px/1.25 at both sizes, with local discovery overrides; desktop navigation inherits 18px and tablet navigation uses 16px rather than the proposed 14px. Mobile stack gap 20px, form gap 18px and empty-state padding 40px sit outside the proposed spacing steps. Focus uses a 2px ink outline, 4px offset and 3px paper shadow. `--muted: #585044` is an additional secondary-text color; `--line: #857a6b` is declared but currently unused. These observations are implementation evidence, not new approved tokens or a claim that the full rendered accessibility and journey checks have passed.

Final compact-height translation was rechecked against the formatted stylesheet on 2026-11-05. At desktop widths of at least 960px and heights of at most 720px, the signed-in header is 80px, Discover/My List headings are 44/48px, onboarding headings are 40/44px, favorite artwork is 136px high with 18/22px captions, and featured artwork is 300px high with a 36px title. Phone featured artwork is 216px high. The sidecar reflects the compact favorite/caption rules and the existing tablet navigation and phone input sizes. The mood request is an expanded disclosure before picks and collapses to “Adjust your request” after picks; details presents its title before the cover. These adaptations preserve usable controls in the approved compact review sizes. Section-local profile persistence is enforced by server-side field filtering; it is behavior evidence rather than a design-token addition.

Final narrow-screen check: below 360px, the owned entrance uses a 30px wordmark and 32px display copy with 16px padding/gap to avoid overlapping the two typographic elements. The required 390px and wider compositions are unchanged.
