# Journeys and state contracts
|Trigger|Pending and success|Failure and recovery|
|---|---|---|
|Create email account|Disable repeated submit; transition to verification with entered address. Refresh can resume pending verification.|Associate validation with field, focus first invalid input, preserve safe values. Never persist passwords or verification codes.|
|Verify / resend|Allow paste and autofill. Match branch provider method. After verification check server session, then onboarding state. If provider requires reauthentication, present one explicit sign-in action with address filled.|Invalid code: inline retry. Expired: resend; observe real server cooldown. Change email via supported provider flow. Redact codes, tokens and email from diagnostics.|
|Google / email sign-in|Show pending; verify callback origin, cookie and server identity. Completed profile → Discover; incomplete → saved onboarding step.|Cancellation offers retry/email. Failed profile read gives Retry. Never interpret a transport error as new user.|
|Recover password|Show neutral request confirmation; consume valid reset token; return to sign-in after update.|Expired token goes to request-new-link; no account enumeration.|
|Choose favorites / finish|Keep selections by catalog ID across searches; retain safe, user-scoped draft across Back/refresh. Save once. Resolve checked session before opening Discover.|Discard out-of-order results; show list fetch failure separately from empty. Submission failure retains draft and current step. Preserve compatibility with legacy favorite-title strings.|
|Request picks|Server applies whole-library exclusions, dismissals, valid mode and session passes before ranking; recheck after cache/ranking. Associate reasons with stable IDs. Deduplicate repeated generation.|Show fewer eligible picks or no-match explanation. Catalog failure and Groq failure have separate retry paths. Never silently add blocked titles.|
|Act on a recommendation|Save → Plan to Watch; Already watched → Completed and optional taste. Pass opens Not tonight, Not interested, Strongly not interested. Temporary pass lasts session. Durable dismissal survives devices. Optional reason informs preference. Undo restores prior state.|Pending disables duplicate action. On write failure restore prior UI and offer retry. Revalidate cached batch after undo or edit.|
|Change library / profile|Show old and pending value, then persisted result. Restore hidden title explicitly. Removal uses confirmation or recoverable undo.|Scope by verified owner. Retain unsaved edits; cancel preserves last saved state. Never reveal another user's private entries.|
Navigation retains return context from details, restores drawer-trigger focus, closes with Escape, and announces status without interrupting typing.

## Acceptance before merge
Real route screenshots at 390×844 and 1440×900; compact desktop at 1363×647; keyboard-only and reduced-motion journeys. Check 200% zoom, long titles, missing artwork, broken network, rapid repeated clicks. Test real preview email verification and Google return/cancellation with branch auth configuration; distinguish mocks from provider results. Verify firebase export/import dry run separately by source UID and target user, keep backups, reconcile fields and statuses, preserve rerun/rollback safeguards. No production migration, merge or deploy during UX review.
